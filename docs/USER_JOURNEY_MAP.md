# Vorqa AI User Journey Map

## Purpose

Sprint 21A narrows the product story around one dominant journey:

Organization -> Project -> Execution Workspace -> VORA Intelligence -> Decision / Report / Action

The goal is clarity. Vorqa keeps all existing modules, but the interface should guide users toward project execution first.

## Current Journey

1. Visitor lands on Genesis or the public landing page.
2. Visitor registers or logs in.
3. Authenticated user enters the command center.
4. The sidebar exposes many equal destinations: projects, tools, organizations, marketplace, RFQ, quotations, contracts, billing, admin, notifications, history, saved, favorites, pricing, settings.
5. User chooses a project or explores broad modules.
6. VORA appears in multiple contexts: tools, project workspace, dashboard widgets, and history.
7. Reports, decisions, RFQ, quotations, and contracts exist, but the route hierarchy makes them feel like parallel products.

## Target Journey

1. Visitor
   - Understands Vorqa as the future workspace for construction intelligence.

2. Genesis / Landing
   - Creates the premium first impression.
   - Offers a safe skip and clear path into the product.

3. Register or Login
   - User enters with an account and session.

4. Organization
   - User understands the company/workspace context.
   - Organization membership, departments, employees, and roles support the project.

5. Project
   - User selects or creates the construction project.
   - Project identity becomes the main working context.

6. Project Workspace
   - The primary authenticated experience.
   - Execution is grouped around overview, VORA, tasks, timeline, budget, documents, knowledge, team, and reports.

7. VORA Intelligence
   - VORA reviews organization and project context.
   - VORA helps convert project information into outputs, risks, reports, checklists, and decisions.

8. Execution
   - User acts on tasks, timeline, budget, documents, knowledge, and team coordination.

9. Report / Decision / Action
   - Reports, RFQs, quotations, contracts, saved outputs, and notifications are downstream actions.
   - They remain accessible but should not compete with the project workspace as the central product.

## Product Principle

Every authenticated page should answer:

- Which organization am I in?
- Which project am I working on?
- What does VORA recommend next?
- What action should I take now?

## Primary Navigation Model

Primary:

- Command Center
- Projects
- VORA
- Organizations
- Marketplace
- More

Secondary under More:

- RFQ
- Quotations
- Contracts
- Billing
- Admin
- Notifications
- Tools
- History
- Saved
- Favorites
- Settings

## Acceptance Standard

The user should feel that Vorqa is not a collection of modules. It should feel like one construction operating journey with VORA as the intelligence layer.
